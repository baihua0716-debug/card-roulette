# 卡牌轮盘

卡牌轮盘是一个黑卡 / 白卡概率博弈网页游戏。玩家和电脑轮流从未知牌序中出牌，通过判断概率、使用技能、管理血量来击败对方。

游戏已经改造成纯静态网页，可直接部署到 GitHub Pages，不需要后端服务、Streamlit 或构建步骤。

在线游玩：<https://baihua0716-debug.github.io/card-roulette/>

## 基本规则

1. 每轮固定生成 8 张牌，牌堆中至少有 1 张黑卡和 1 张白卡。
2. 黑卡会造成伤害，白卡不会造成伤害。
3. 玩家可以选择“对电脑出牌”或“对己方出牌”。
4. 对电脑出牌后，无论抽到黑卡还是白卡，都会进入电脑回合。
5. 对己方出牌时，如果抽到白卡，可以继续行动；如果抽到黑卡，会对自己造成伤害并结束回合。
6. 双方初始血量为 6。任意一方血量归零，对局结束。
7. 如果当前牌堆只剩白卡，可以直接结束本轮并生成新牌序。
8. 当前牌堆抽空后，会生成新一轮牌序，并由玩家先行动。
9. 每次生成新牌序时，双方各获得若干随机技能，最多持有 8 个。技能不是等概率出现。

## 技能说明

- 探测：查看当前这一张牌是黑卡还是白卡。
- 洗牌：洗掉当前这一张牌，并公开它是黑卡还是白卡。
- 疗愈：回复 1 点血量，不能超过血量上限。
- 增幅：下一张由使用者打出的牌会消耗此状态；若为黑卡则造成 2 点伤害。
- 冻结：让另一方跳过下一个回合。
- 预示：随机预知未来某一张牌的信息，不包括当前这一张。
- 转换：反转当前这一张牌的颜色，但不公开转换前后的结果。
- 夺取：夺取另一方一个技能，并立即使用它。不能连续夺取“夺取”。
- 超频：立刻失去 1 点血量。下一次出牌若为黑卡则造成 3 点伤害；若为白卡，超频状态也会消耗。
- 涉险：50% 概率回复 2 点血量，50% 概率失去 1 点血量。

增幅和超频不能叠加。若已经处于其中一种状态，不能再使用另一种状态技能。

## 技能权重

- 更常见：疗愈、洗牌、增幅、探测。
- 基准权重：冻结、涉险。
- 更少见：预示、夺取、转换、超频。

## 电脑难度

- 简单：随机行动为主，辅以基础策略判断。
- 中等：使用默认评分模型，综合当前牌面、血量、技能和风险。
- 困难：使用 2 层搜索、玩家威胁评估、技能保留价值评估、技能连招续算、技能组合学习，并对候选行动进行 200 步 Monte Carlo 模拟。

## 自定种子

顶部的“种子”输入框可以进入自定模式。输入任意文本后点击“应用”，游戏会使用该文本生成可复现的随机序列；在相同种子和相同操作顺序下，牌序、技能和随机结果会保持一致。清空输入框后点击“应用”会恢复随机开局。

## 项目结构

- `index.html`：网页入口。
- `styles.css`：响应式界面样式。
- `game-core.js`：游戏规则、技能效果、状态机和电脑 AI 的兼容入口。
- `game-random.js`：随机数、种子、加权抽样和洗牌工具。
- `player.js`：玩家/电脑角色模型。
- `app.js`：DOM 渲染和玩家交互绑定。
- `tests/state-machine-regression.mjs`：核心状态机回归测试。
- `streamlit_devil_card_game.py`：原 Streamlit 版本，保留作参考。

## 本地预览

在项目根目录运行任意静态服务器即可，例如：

```powershell
python -m http.server 8000
```

然后访问：

```text
http://127.0.0.1:8000/
```

## 回归测试

```powershell
node tests/state-machine-regression.mjs
```

如果系统 `node` 不可用，也可以使用 Codex bundled Node 运行同一个测试。

## GitHub Pages 部署

1. 将项目推送到 GitHub 仓库。
2. 打开仓库 `Settings`。
3. 进入 `Pages`。
4. 在 `Build and deployment` 中选择 `Deploy from a branch`。
5. Branch 选择 `main`，目录选择 `/root`。
6. 保存后等待 GitHub Pages 构建完成。
